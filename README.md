## 무엇이 느렸나

배포된 번들(`index-Cxd2QxXN.js`)을 역분석해 실행 경로를 추적한 결과,
앱을 켤 때마다 아래 네 구간이 **직렬로** 이어지고 있었습니다.

| 구간 | 기존 동작 | 비용(모바일 기준) |
|---|---|---|
| ① 앱 셸 | 서비스워커가 `navigate`를 **network-first**로 처리 → 매번 `index.html`을 네트워크에서 받음 | 200~600ms |
| ② JS 파싱 | 단일 번들 850KB(gzip 218KB) | 300~600ms |
| ③ 인증 | `onAuthStateChanged`가 끝날 때까지 전체 화면 스피너. 저장된 세션을 읽고 만료 토큰을 갱신(securetoken 왕복) | 200~500ms |
| ④ 썸네일 | 인증이 끝난 뒤에야 Firestore 구독 시작 → 그 다음 사진 1장당 IndexedDB 트랜잭션 1개 | 장수에 비례 |

Firestore 오프라인 영속 캐시(`persistentLocalCache`)는 이미 켜져 있었습니다.
문제는 **캐시가 느린 게 아니라, 캐시를 읽기 시작하는 시점이 늦었다**는 것입니다.

## 무엇을 바꿨나

### 1. `public/sw.js` — 앱 셸을 기다리지 않음 (가장 큰 효과)

- `navigate` 요청을 **cache-first + 백그라운드 갱신**으로 변경.
  캐시된 셸을 즉시 돌려주고, 새 버전은 조용히 받아 두었다가 다음 실행에 반영합니다.
- **사진 캐시를 셸 캐시와 분리**(`lifelog-photos`).
  기존에는 `CACHE` 상수를 올릴 때마다 캐시된 사진까지 전부 지워져서,
  앱을 업데이트할 때마다 사진을 다시 받아야 했습니다. 이제 배포와 무관하게 유지됩니다.
- 해시가 붙은 `assets/*`는 내용이 절대 안 바뀌므로 재검증 없이 cache-first.
- 사진 캐시 항목 수 상한(1200개) 추가.

### 2. `src/App.jsx` — 인증을 기다리지 않고 데이터 구독 시작

마지막 로그인 uid를 `localStorage`에 기억해 두고, 부팅 즉시 그 uid로 Firestore를
구독합니다. 영속 캐시는 토큰 없이도 로컬 데이터를 바로 내어 주므로
**인증 확인과 데이터 로딩이 병렬로** 진행됩니다.
전체 화면 스피너는 "한 번도 로그인한 적 없을 때"만 나옵니다.

uid가 실제 인증 결과와 다르거나 로그아웃 상태면 자동으로 정리 후 로그인 화면으로 갑니다.

### 3. `src/thumbcache.js` — 썸네일을 트랜잭션 하나로 한 번에 읽기

`warmThumbs(keys)` 추가. 기존에는 `<img>` 하나가 마운트될 때마다 IndexedDB
트랜잭션을 하나씩 열어서, 캘린더에 60~200장이면 트랜잭션도 그만큼 생겼습니다.
이제 첫 스냅샷에서 필요한 썸네일을 **한 번에** 읽어 메모리에 올린 뒤 그립니다.
→ 스켈레톤 → 이미지로 깜빡이지 않고 처음부터 채워진 채로 뜹니다.
(로컬 읽기가 느린 기기를 대비해 250ms 상한을 두었습니다.)

`objectURL`은 실제로 화면에 필요한 시점에 지연 생성해 메모리도 아낍니다.
사진 모아보기 화면도 열릴 때 한 번에 워밍합니다.

### 4. `index.html` — 렌더링 차단 제거

- Google Fonts CSS를 `rel="preload" as="style"` 비차단 로드로 변경.
  기존 `<link rel="stylesheet">`는 폰트 서버 응답이 올 때까지 첫 화면을 막았습니다.
- 인증·Firestore·Storage 호스트에 `preconnect` 추가 → TLS 핸드셰이크 선행.
- JS 파싱 전에도 배경색이 칠해지도록 인라인 스타일 추가(흰 화면 방지).
  저장된 테마를 즉시 반영해 다크모드의 흰 번쩍임도 없앴습니다.

### 5. 번들 축소 — `vite.config.js`, `firebase.js`, `photos.js`, `migrate.js`

- `firebase/storage`(77KB)를 **지연 로드**. 첫 화면에는 필요 없습니다
  (사진 URL은 Firestore 문서에, 썸네일은 IndexedDB에 이미 있음).
- `@capacitor/core`(21KB) 정적 import 제거 — `window.Capacitor` 직접 판정으로 대체.
- `migrate.js`(백업 가져오기·사진 최적화)를 설정 화면에서만 동적 import.
- 벤더를 `vendor-react` / `vendor-auth` / `vendor-firestore`로 분리.
  총 바이트는 비슷하지만, **앱 코드만 고친 배포에서는 벤더 청크 파일명이 그대로**라
  서비스워커 캐시에서 재사용됩니다. 업데이트 후 첫 실행이 훨씬 가벼워집니다.

## 배포 후 주의사항

1. **서비스워커는 두 번째 실행부터 적용됩니다.** push 후 앱을 한 번 열면 새 SW가
   설치되고, 다음 실행부터 빨라집니다. (기존 `lifelog-v1` 캐시는 자동 삭제)
2. 앞으로 셸을 강제로 새로 받게 하려면 `public/sw.js`의 `SHELL_VERSION`만 올리면 됩니다.
   사진 캐시는 그대로 유지됩니다.
3. 저장소 루트의 `thumbcache.js`는 `src/thumbcache.js`와 중복된 미사용 파일입니다.
   지워도 무방합니다(이번 변경에는 포함하지 않았습니다).
